# ADR 0016 — Pinned Git repository browsing and single-file code import (A44)

Status: implemented within the bounds below, 2026-10-04. Builds on ADR 0007 (code blocks run only in an isolated sandbox).

VISION §7.9 asks for browsing repository content at a pinned commit, distinguishing kinds of content, selecting an entry point, dependency environment and contract, and recording URL, commit, paths, checksums, license, dependencies and local modifications. Browsing must never run installation scripts. `python/repos/` and `services/control/repos_api.py` implement a bounded version.

- **Fetch, never check out.** A remote (absolute local path, `file://`, `https://`, `ssh://` or scp-style) is fetched into a bare mirror `repos/<sha256(url)[:24]>.git` under the workbench. Branches, tags and `HEAD` are fetched into a private ref namespace; a requested revision resolves to a full commit SHA. Git runs with `core.hooksPath=/dev/null`, a protocol allowlist (`file`, `https`, `ssh`; `ext::` and other helpers refused), no system config, no terminal or askpass prompts, no submodule recursion, and a 120 s timeout. URLs that embed credentials are refused; authorization uses the environment's own Git/SSH configuration (HOME is preserved for credential helpers) and is never stored. Every safety setting is passed with `-c`, which takes precedence over user configuration. A test points a user `~/.gitconfig` at a hook directory (Git runs `reference-transaction` hooks during fetch) plus a hostile `diff.external`, and nothing runs. Removing the `core.hooksPath` override makes that test fail.
- **Read-only inspection.** Trees come from `git ls-tree`; bytes from `git cat-file blob`, so clean/smudge filters, LFS downloads and textconv never run. Comparisons use `git diff --no-ext-diff --no-textconv`. Entries are classified as Python source, installation script (`setup.py`, `conftest.py`, `noxfile.py`, root `*.sh`, …), dependency manifest, license, dataset, model weights, configuration, documentation, notebook, large-file pointer, submodule gitlink or symlink. Symlinks are never followed and submodules are never fetched. Paths are repository-relative only. Displayed text is capped at 256 KiB.
- **Static metadata only.** Dependencies come from `requirements*.txt`, `pyproject.toml` (`[project]` dependencies and optional groups, via `tomllib`) and `setup.cfg` `install_requires`; pinned (`==`) and unpinned requirements are distinguished. `setup.py` and build backends are reported as executable installation code that was not run, so dependencies they compute are not extracted. Option lines such as `-e .` are reported, not followed. License text is matched by keyword to an SPDX guess, labelled as needing verification. Python files are read with `ast.parse`, never imported: top-level functions, parameters and literal defaults, imports, and repository-local imports.
- **Explicit wrap of one function.** The user picks a top-level plain function in a single-file module and declares which parameters are tensor inputs or node settings, plus the output names. Modules that import other files of the repository, or that define their own `run`, are refused with the reason. The generated code block is the pinned file text plus a small adapter `run(...)`. A record (`void-repo-import/1`: URL, commit, tree, path, blob, file sha256, function, parameters, imports, license, declared dependencies and notes, chosen pins, interface, generated source sha256) is written content-addressed under `repos/imports/<sha256>.json`; reads verify the hash. The block carries `origin` (import id, URL, commit, path, blob, function, imported source hash), which is part of the graph's semantic hash, so a different commit is a different identity. Chosen pins become the block's dependencies and are checked by the sandbox when it runs; nothing is installed.
- **Execution boundary.** Imported code runs only when the block is tested or executed, in the ADR 0007 sandbox (scrubbed environment, limits, declared effects). The guard is best-effort and not a hostile-code boundary, so the user should review the source shown before importing.
- **Local modifications and deliberate updates.** `/api/repos/origin-status` compares the block's current source hash with the imported one; the editor shows "unmodified pinned import" or "locally modified since import". The import dialog compares the selected file between the pinned commit and any other revision (patch view). Updating means re-importing at the new commit, which creates a new import record and block identity; rolling back means using the earlier import.

Tests (`tests/test_repos.py`) use a real local Git repository whose `setup.py`, `conftest.py`, package `__init__.py`, `install.sh`, source-repo `post-checkout` hook and `.gitattributes` diff/filter drivers would each create a marker file if executed. Resolve, browse, read, inspect, compare and import leave no marker.

Remaining: notebooks as entry points (multi-file pure-Python packages: see the addendum), wrapping data/config/model files as typed sources, LFS object download, submodule fetch, dependency installation or environment creation, hosted-provider (GitHub/GitLab) API browsing and credential UI, history/blame views, and automatic mirror retention. Explicit cleanup was added later: `GET /api/repos/mirrors` lists fetched mirrors with size and import counts, and `DELETE /api/repos/{id}` removes one while keeping import records and imported blocks; a fresh resolve restores browsing.

## Addendum: multi-file packages (2026-10-04)

The single-file restriction is lifted for pure-Python repository packages. `inspect_python` resolves, with `ast` only, the closure of repository modules reachable from the entry file:
- absolute and relative imports, including `from pkg import submodule`;
- the `__init__.py` of every parent package, because Python executes those on import.

Unresolvable relative imports, unreadable modules, and bundles over 50 files or 1 MB are refused with the reason. The generated block embeds each module's exact pinned text behind an in-memory import hook (`importlib` meta-path finder/loader). Nothing is read from disk at run time; a test moves the source repository away and the block still runs. All bundled code executes only inside the code-block sandbox under its declared effects: the booby-trapped `pkg/__init__.py` in the test fixture is refused by the guard there, and no marker is written. Every module's path, blob, sha256 and size is recorded in the import record and the block `origin`, which is part of the semantic hash. A three-module package with relative imports computes the expected values in the sandbox (test and Chromium journey).

Still not supported: compiled extensions, notebooks, namespace packages without `__init__.py`, data files read by the package at import time (they would need a declared `file_read` effect and are not bundled), and installing third-party dependencies.
