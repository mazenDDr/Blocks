# ADR 0012: Native fitted pipelines, local releases and measured production investigation

Status: accepted (Milestone 7). Sources: VISION §17.5–17.8, §19.5, §23 Milestone 7, A50/A59–A63. Builds on ADR 0002/0003/0004 and the immutable run/CAS contract.

1. **A bounded serving adapter.** Native scikit-learn LinearRegression/LogisticRegression pipelines are the first registered/served family. The existing tabular worker now captures its actual estimator, fitted imputer/one-hot/scaler objects and ordered inference path. Source, profile, split and row-filter operations remain recorded training-only decisions; they do not remove inference rows. Typed selection/casting and fitted transformations retain their native implementation. Unsupported table paths, or transforms requiring the target, produce an explicit `inference_refusal`; registration cannot silently substitute semantics. Existing summaries remain readable. Old runs need a supported rerun to record fitted objects; registration never trains.
2. **Pin all execution identities.** The pipeline manifest pins run/graph/model/fitted state, raw schema/nullable policy, ordered features, output task/classes, source file identity and frozen table artifacts, evaluations, native dependencies, and hashes of the serving adapter and shared transform implementation. Tokenizer is explicitly null for this tabular adapter; custom code is unsupported. Inference uses no source path and never refits. Artifacts and environment are rechecked even when native objects are cached. Internal worker-generated pickles are hash/membership verified before loading; there is no pickle upload or arbitrary path API. The local workbench storage is trusted, as in existing checkpoint loading.
3. **Registry and release records.** `production.sqlite` stores immutable records referencing JSON in the existing CAS, movable aliases, atomic routes and append-only lifecycle events. Version records include owner, intended use and limitations. Aliases resolve to exact version IDs when a candidate is created. Candidates pin one replica, CPU placement, synchronous bounded batch, concurrency/queue limits, timeout, session mode and input capture policy. Candidate creation performs a real native warmup and records compatibility evidence; deployment is a separate explicit action. Compare-and-swap against the previewed prior route rejects stale actions. Rollback accepts only a previously deployed release and records both actual old/new identities.
4. **Real local and staging routes.** Both `/api/serve/local/{namespace}/predict` and `/api/serve/staging/{namespace}/predict` execute native inference in this same local FastAPI process. Staging is a distinct local namespace/route, not an external cluster. Health/readiness checks verify the currently routed artifacts/environment. Remote deployment, autoscaling, multi-process replicas, dynamic batching, asynchronous batch jobs and streaming are not implemented. No remote deploy control exists.
5. **Admission and session semantics.** Requests pin the route/version before admission. A bounded semaphore limits active requests; a bounded wait queue rejects overflow (429) and expires deadlines (504). Timeouts/cancellation do not interrupt a native call; they prevent its state commit and discard its result. The optional stateful application is a durable request counter isolated by release/user/session, with serialized updates. The native estimator stays stateless. User/session fields are caller-declared local identities, not authentication. Request IDs are idempotent per user and include exact input/release/session identity; replay cannot update the counter again. Single-owner restart marks incomplete requests failed (503), never resumes their forward pass or duplicates state. Deploy/rollback does not rebind in-flight requests.
6. **Recorded traces and explicit privacy.** Every admitted/rejected inference request records status/error, request/release/version/run/source/graph/preprocessing/evaluation lineage, input hash, observed validation/queue/preprocess/inference/postprocess timing, and result/state when committed. Input capture defaults off; raw and transformed values are retained only when enabled in a new candidate. Isolated replay requires captured inputs and executes the pinned version without touching routing/training/session state. `totalMs` covers admission through inference/error handling; it excludes persistence/HTTP encoding, which the load client's end-to-end latency includes. Cancellation has its own lifecycle event. Registry/source manifests already contain bounded training previews from existing research artifacts.
7. **Measured traffic with generator accounting.** One bounded loopback HTTP generator targets a recorded deployed release on this server's own port, never an arbitrary host. Steady/ramp/burst modes are rate-driven; closed-loop is response-driven. Payload batches rotate to exercise request-size distributions. Limits are 30 s / 500 arrivals / 16 generator workers, with 0–10 separate warmup requests. Occupied generator slots cause counted dropped arrivals; queue/HTTP errors, timeouts and unexpected statuses remain distinct. Report configured/offered/sent/successful rates, drain time, latency percentiles, queue time, payload/release identities, and sampled RSS/process CPU. Resource scope includes both the local server and generator, warmup and drain; cost is not measured. Cancellation stops new arrivals and drains already submitted bounded requests. Immutable results survive restart and can be found by job ID or result hash. A small local load test makes no arbitrary scale guarantee.
8. **Monitoring is descriptive evidence.** The reference contains the first 2,000 rows in recorded training order, with truncation/count metadata and original aligned targets retained separately. Monitor the latest 1,000 recorded requests for a selected release/time window. Input numeric drift uses native scipy two-sample KS plus observed means/missing fractions; categorical/prediction frequency drift uses explicit total variation. Regression prediction drift uses KS. Reference predictions are actual pinned native forward passes. Label-based accuracy/MSE/MAE uses only explicitly submitted aligned labels, records label delay and request evidence, and is unavailable without labels. Conflicting ground-truth overwrites are refused. Loaded example labels are labelled training-reference/in-sample evidence; they are not a held-out production benchmark. Drift never triggers automatic rollback or training.
9. **Editor and evidence.** The Production workspace provides Registry, Release, Requests, Traffic and Monitoring views. All mutations are explicit working controls, JSON inputs are validated by the existing API contract, and missing results stay absent/unavailable. Source runs open in the existing research view. `production_sensors` is a deterministic labelled SYNTHETIC example; `production_journey.py` executes train → registry → request → labels → replay → measured HTTP → deploy/rollback through real HTTP. Tests compare native fitted outputs, raw preprocessing order, session isolation/cancellation, actual different-weight rollout, integrity, source independence, restart and real HTTP patterns.

## Limits / future work

No registry/serving adapter for PyTorch CNN checkpoints, domain models, agents, RL, Keras/JAX or unsupervised models yet. Those research workflows remain available independently. No authenticated multi-user boundary, cloud deployment, canary/shadow traffic splitting, online learning, forced model updates, remote resource attribution or retention/garbage collection. This adapter requires one owning control process; avoid multiple uvicorn workers on the same workbench. A worker or control-service crash cannot be presented as a successful inference. Future deployment adapters must preserve these manifests and actual route/request identities, and must be genuinely tested against their destination.
