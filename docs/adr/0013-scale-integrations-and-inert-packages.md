# ADR 0013 — Bounded scale integrations, explicit tracking and inert packages

Status: implemented within the scope below, 2026-10-04.

The workbench needs real worker/tracker recovery and reusable community artifacts without making local research depend on an external account or executing imported code automatically.

1. **Worker protocol:** `void-worker/1` is an authenticated HTTP protocol tested against a separate process on the same machine. Its shipped server binds only 127.0.0.1 and the client accepts only explicit `http://127.0.0.1:PORT`. Bearer credentials are an environment reference and never included in saved/exported job payloads. This is a loopback CPU adapter; cross-host encrypted transport, GPU, distributed scheduling and team authentication are unavailable. Native tabular CSV/preprocessing/linear/logistic/metrics operations only, at most 64 nodes, 8 MiB input snapshots, two active jobs, 12 MiB HTTP body, 32 MiB artifact transfer. Native compute is not forcibly interrupted; cancellation is checked between nodes. Admission bounds are not a wall-time/GPU guarantee.
2. **Identity and recovery:** immutable input bundles bind original graph/settings/seed and CSV bytes. The worker materializes private content-named source files, records its distinct execution graph hash and uses an idempotent job fingerprint. Durable intentions are saved before submission; lost acknowledgement/reconnect reuses a known job. A submission failure is not retried as a new successful run. Terminal events/artifacts are downloaded with membership, size and SHA checks; metadata imports atomically and idempotently. Imported native pickle artifacts are untrusted for local serving. No shared filesystem is assumed; no source path is read by the worker. An intention without a recorded worker run requires investigation/new job, never silent re-execution.
3. **Native tracking with explicit sharing:** snapshots of terminal runs are queued durably with run ID/hash/status, opt-in actual numeric metrics and explicitly selected sklearn evaluation-summary artifacts. Raw records, graph/config/code and model pickles are not shared by this bridge. Destinations are local native MLflow SQLite or native W&B offline. No online account or cloud upload is performed. MLflow recovers the external run by the immutable export tag and checks history and deterministic content-addressed artifact paths before retrying. Native confirmation followed by lost local acknowledgement does not duplicate confirmed run/metric/artifact mappings. W&B offline is one immutable export, not live offline resume: rebuild only an unconfirmed owned pending directory, finish native logging, atomically confirm the directory, and reuse confirmed mappings. Native git/code/system metadata capture is disabled. One owning control process serializes bridge operations. Deleted/externally changed confirmed destinations require explicit investigation; no background upload policy is implied.
4. **Dependency isolation:** MLflow-skinny 3.16.1, W&B 0.30.0, SQLAlchemy 2.0.48 and Alembic 1.18.4 use `.venv-trackers`; complete installed lock is retained. Their protobuf 6 dependency must not replace training's verified protobuf 7.36.2. Bridge subprocesses read immutable JSON payloads and native artifact paths with finite timeout, and preserve pending intentions on failure. Local execution works without the optional environment; syncing requires it.
5. **Trusted extension SDK:** manifests pin exact operation/version/source hash/native dependencies, port/settings schema, state/effects, inspector metadata, docs, example and numerical cases. The current SDK supports pure tabular operations with usable default settings. Conformance runs actual native code against declared expected outputs, inferred schema, repeated outputs and input immutability in a separate bounded process. This checks declared examples, not an arbitrary-code security proof. Activation of third-party Python is explicit trusted startup `VOID_PLUGIN_MANIFESTS`; opening/importing a project never installs or executes code. Workers inherit explicit activation and record exact package identities. The bundled offset is a teaching/example operation, never a claimed learned transform.
6. **Inert reusable project package:** content-addressed JSON carries graph, UI, exact operation dependencies, environment requirements and optional explicitly selected CSV snapshots, max 8 MiB/64 resources. No credentials or run artifacts are included. Structured secret fields and credential-bearing URLs are refused, not resolved. Requirements outside embedded CSVs remain explicit. Native environments are declared requirements, not automatically installed. Import verifies hashes/paths and preserves unknown operations, while unavailable or different pinned dependencies produce stable `E_PACKAGE_DEPENDENCY` execution refusal. It writes a project, never runs it. Freeform researcher text is not a general secret scanner; choose appropriate material to export.
7. **Scientific evidence and accessibility:** recorded baseline/variant summary values appear in a metric table; researcher conclusions are immutable CAS evidence linked to exact run/source/fitted/evaluation summaries. Existing inspection and production promotion controls complete the bounded connected PostgreSQL SYNTHETIC journey. There is no debugger intervention inside sklearn internals. Keyboard controls select nodes/wires and connect ports using the exact existing mutation/validation path; native form controls and visible focus enable the recorded reference journey. Broad screen-reader certification and external-user onboarding are not claimed.
8. **Acceptance and measurements:** `ACCEPTANCE.md`/`acceptance.json` map A01–A64 to tested scope or explicit unimplemented behavior. A09 dependency-scoped numerical caches and A44 repository source-code import remain unavailable. `benchmarks/results/m8_local_worker.json` records three real CPU local-vs-HTTP journeys with exact native evaluation agreement. Timings include HTTP/polling/startup/transfer and do not establish a remote-hardware speed claim. Existing A19 backend benchmarks remain separate.

Native references: [MLflow client](https://mlflow.org/docs/latest/api_reference/python_api/mlflow.client.html), [W&B Run](https://docs.wandb.ai/ref/python/experiments/run/), [W&B persistent-record schema](https://github.com/wandb/wandb/blob/main/wandb/proto/wandb_internal.proto) and [native record format](https://github.com/wandb/wandb/blob/main/wandb/sdk/internal/datastore.py). Installed versions and native records are authoritative for this implementation.

Future work: cross-host TLS/provisioning, GPU/distributed workloads, online trackers and credentials, incremental streaming exports, additional source/serving/SDK families, live team permissions, complete assistive-technology evaluation and actual external-user onboarding. These controls remain absent.
