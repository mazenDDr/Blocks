# ADR0026: Reproducible editor smoke and native CI baseline

Status: accepted. Extends the verification baseline requested in HANDOFF §22. No native execution/serving identity files change.

1. **Actual native execution, no provider substitute.** `serving_state` is a labelled SYNTHETIC teaching graph containing real LangGraph set-state nodes, integer/thread reducers, a bounded history and a declared output template. It makes zero language-model calls. Assertions concern native state and control-plane behavior, never learned answer quality. Live Ollama remains independently required on the Mac; this fixture does not replace those tests.
2. **Owned isolation and lifecycle.** `tools/editor_smoke.py` runs the current Python interpreter, uvicorn, the installed editor/pnpm and installed Chrome on automatically chosen loopback ports. Use a new workbench/evidence directory outside the repository and an ephemeral shared token. Drop inherited application/plugin/provider/tracker settings; never reuse an existing backend, workbench, browser profile or token. Ports are selected then bound, so an intervening collision fails startup; never kill its owner. Services run in owned process groups, with readiness, total browser deadline, SIGTERM cleanup and bounded SIGKILL fallback. Success, failure and interruption persist runner status and cleanup return codes. An uncatchable kill of the runner or host crash is not a cleanup guarantee.
3. **Versioned source, external execution evidence.** Pin Puppeteer Core **25.12.0** in editor dev dependencies and lockfile; no browser download or runtime dependency. Version the Python runner and JS journey source, then copy the executed browser script outside the repo beside logs/screenshots/evidence. This makes the durable baseline available to a fresh clone while keeping ad hoc scripts/generated artifacts outside Git. Chrome is explicitly installed/resolved, as required by [Puppeteer Core](https://pptr.dev/guides/installation).
4. **Real UI journey and failures.** Picker→source worker→register actual candidate→warmup/deploy→two native turns→inspect→reviewed fork→independent branch→reset checkbox→null head→captured historical replay→fresh thread→read-only monitoring. Check whole native state, exact predictions/revisions/thread isolation, zero model calls, immutable receipt lineage, unchanged cleared head during replay, zero runtime/API/console errors and four monitored successes. Capture review/reset/monitor screenshots and actual trace values. Fix the missing favicon rather than discarding its console error. Known warning text is recorded; any console error fails. On failure, preserve screenshot/visible page text when the browser remains available.
5. **GitHub baseline, bounded claims.** Workflow uses Python3.13, Node25.9.0 and pnpm10.33.0, pinned Python dependencies plus isolated tracker environment and the existing PostgreSQL installer. Run the ordinary offline native suite, editor build/typecheck, coverage-current check and model-free Chrome journey. Read-only repository permission, one run per ref, 35-minute bound; upload actual JUnit/logs/evidence/screenshots for seven days on success or failure. Do not upload workbenches, CAS weights, generated browser profiles or tokens. [GitHub workflow artifacts](https://docs.github.com/en/actions/tutorials/store-and-share-data) preserve observations, not guarantees that all platforms/providers work. Record the actual hosted run outcome separately from local verification.

Remaining scope: browser coverage beyond this representative native conversation flow, hosted live Ollama/GPU/other-platform matrix, branch-protection policy, deployment, browser-version pinning, production bundle serving/authentication, backup/restore/upgrade and formal accessibility/performance/real-user benchmarks. The baseline uses the existing development proxy; a successful editor build is a separate check, not a claim to have tested a deployed production web server.
