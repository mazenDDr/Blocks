# ADR 0025: Reviewed reset and fork of native serving conversations

Status: accepted. Builds on ADR 0024. Native adapter/compiler source bytes remain unchanged; this extends control-plane session management without invalidating existing versions.

1. **Explicit current-checkpoint review.** POST `/api/production/releases/{rid}/conversation/reset|fork` requires caller-declared user/session, an action ID, the inspected revision/checkpoint SHA and a bounded reason. Fork additionally requires a different unused destination session under the same release/user. Only live completed checkpoints may be reviewed; empty/reset sessions cannot be reset/forked again until a successful turn. No historical arbitrary checkpoint import or cross-release/version migration. Source bytes/pinned native version are verified; stateless releases refuse these actions. Shared-token protection applies when configured, without pretending caller user keys are authenticated ownership.
2. **Serialize with native turns.** Use the owning runtime’s existing per-release/user/session locks, with deterministic ordering when two scopes are involved and a bounded wait from the release timeout. A waiting action rechecks the exact reviewed head after the active turn; a changed revision/hash refuses rather than applying to unseen state. Different sessions can continue independently. SQLite checks the parent again before mutation. One owning control process remains required; this is not distributed coordination.
3. **Atomic head, receipt and audit.** Add `conversation_actions(user,id,fingerprint,result)` with immutable JSON CAS receipts. The session head mutation, action receipt pointer and lifecycle event share one SQLite transaction. Reusing the same user/action ID and identical release/operation/values returns the original receipt even after later turns; conflicting reuse refuses. No pending action is resumed on restart. A process killed before commit leaves no head/receipt/event change; retry can commit once. A completed action survives disconnect/restart and duplicate retry does not apply it twice. Deadline is checked after serialization before database mutations. Failed CAS/SQLite/event writes can leave orphan immutable bytes, never a partially committed head; broader retention/GC is still absent.
4. **Logical reset preserves evidence.** Increment the session revision monotonically and set its live checkpoint and last-request pointer to null. This avoids reusing old revisions after reset. The next successful turn follows the existing native new-thread/default/input path and gets a fresh native thread ID; its serving revision continues from the reset revision. Old traces, original idempotent requests, snapshots and captured-parent replay remain intact. Reset is not physical deletion or privacy erasure, and it does not cancel or rewrite a completed turn. An empty head has state=null, not invented defaults. No inference is performed by the action.
5. **Independent native fork.** Verify and clone the actual reviewed END checkpoint through the installed native serializer, preserving channel values/versions/versions seen, checkpoint metadata and original history provenance. Rebind the native thread identity in snapshot metadata and envelope; do not regenerate historical assistant IDs/timestamps/call origins. The new scope starts at serving revision 1, with no producing request ID yet. Its first native continuation resets turn state and inherits thread state via the unmodified adapter/compiler. Source head is unchanged; future source/fork turns are independent. Fork does not run a model, summarize history, trim data or silently overwrite a destination. The existing 128 KiB serialized snapshot bound applies.
6. **Editor review and retry.** Management controls appear only for a snapshot matching the selected release/user/session. Show the inspected revision/SHA, reason and unused destination. Reset requires an explicit checkbox stating that earlier evidence is retained. A successful action displays its immutable receipt/lineage and rereads the actual source head; sending a new turn clears stale inspection. Identical retries in the current review reuse the action ID. Changed/failed views never substitute an inferred latest checkpoint. User IDs remain declared isolation keys, not role enforcement.
7. **Evidence.** Native tests cover independent fork reducers/state, fresh reset threads, monotonic revision/idempotency/restart, stale review, active-turn serialization, opposing lock ordering, destination conflicts, slow CAS/lock timeout, SQLite rollback, real process SIGKILL inside both action transactions, token/schema/integrity refusal and retained historical replay. Live Ollama proves exact inherited messages and fresh two-message reset contexts. HTTP and installed Chrome exercise the actual controls; all teaching prompts/reasons are labelled SYNTHETIC, and model text/usage are genuinely produced and recorded by local Ollama.

Remaining scope: physical deletion/privacy erasure, retention/GC, historical checkpoint selection, arbitrary restore/import, cross-release/version migration, session discovery beyond explicit IDs, authenticated ownership/roles, retrieval/memory/effects/interrupt dependencies, streaming and distributed serving. Actions do not address those broader gaps or semantic-answer accuracy.
