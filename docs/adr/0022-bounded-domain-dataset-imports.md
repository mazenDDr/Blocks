# ADR 0022 — Bounded local domain dataset imports and declared provenance

Status: implemented, 2026-10-04. Extends the existing native domain workflows; no new operation family, checkpoint bypass or dependency installation.

## Decision

`POST /api/domain/datasets` converts server-local COCO segmentation JSON + images, CoNLL token labels, or a JSON manifest of WAV paths/transcripts into the existing typed source contracts. `GET /api/domain/datasets` lists imports and checks their manifest/payload integrity. Both routes inherit the optional bearer-token boundary. One import may run at a time; a second receives `E_DATASET_BUSY`. Paths identify local files, never URLs. Member paths must remain within the declared root, including after resolving symlinks.

The caller must explicitly declare `synthetic` as a boolean and supply a nonempty license/permitted-use statement. These are **user declarations, not independently verified facts**. The editor requires both and displays their authority. The converter reads originals once, hashes exact bytes, retains original snapshots plus canonical payload and manifest in the content-addressed store, then atomically materializes the canonical payload and manifest under `domain-datasets/<manifest-sha>/`. The manifest includes source paths/hashes/byte counts, original COCO license IDs/definitions, conversion request, canonical contract/payload hash and converter source hash. A missing or changed imported manifest/payload is refused with `E_DATASET_INTEGRITY`; no silent source fallback.

Applying an import edits draft sources of that family, clears their source truncation, same-family checkpoint continuation and NLP fitted-tokenizer selection, and updates the project's source declaration. It does not overwrite old runs or train automatically. A new native worker run records the imported identity, source hashes and declared license in source/trainer inspection, checkpoint manifests, saved-example responses, inference provenance and production reference provenance. Values from an older inspected run remain visibly tied to that run, even after the draft changes. Legacy fixture declarations remain supported; an undeclared raw corpus reports unknown synthetic status/license.

## Conversion semantics and bounds

- All kinds: 2–256 records; at most 64 MiB cumulative input bytes, 8 MiB JSON/text and 64 MiB decoded canonical arrays/payload. Originals must exist at import time; later training reads canonical data, and saved inference uses only pinned internal artifacts. No network downloads, uploads, dependency installation, streaming conversion or general dataset browser.
- COCO: RGB PNG/JPEG at declared uniform dimensions, 4–512 pixels per dimension, 1–4 categories, at most 64 instances/image and one common schema of at most 128 keypoints. Sparse category IDs are mapped to contiguous model labels with the original mapping recorded. Native pycocotools polygon/uncompressed-RLE/compressed-RLE decoding; run lengths are checked before native decoding. Boxes convert from xywh to xyxy in float32 without implicit clipping/refit. Visibility 0/1/2 and declared disjoint horizontal flip pairs are preserved. Separate masks retain overlaps; the existing semantic target gives later annotations precedence. Crowd, box-only annotations, heterogeneous geometry, non-RGB images and missing/invalid masks are refused. Bounds are specific to the existing tiny segmenter, not support for the complete COCO corpus.
- CoNLL: UTF-8 whitespace columns with caller-selected token/label indices, blank-line sentence boundaries and DOCSTART boundaries. Strict IOB2 refuses stray `I-*` and malformed tags. At most 4,000 reconstructed characters/sentence and 32 entity types. Canonical text joins tokens with one ASCII space. Entity offsets refer to **reconstructed text**, not raw file bytes; original tokens/tags and line numbers are retained. WordPiece training and existing subword-label policy remain explicit and native; no IOB1 repair or recovery of unavailable original whitespace.
- WAV: JSON array of `{id, file, text}`; scipy reads PCM WAV. Uniform sample rate 1–96 kHz, uniform 1–4 channels, 512–32,000 samples/channel; transcript 1–256 characters, at most 64 distinct characters. Unsigned 8-bit uses `(x-128)/128`; signed PCM divides by `2^(bits-1)`, including SciPy's left-justified 24-bit representation; floating PCM converts to float32 without amplitude scaling and must remain finite in [-1,1]. No implicit resampling, trimming or downmix during import. Canonical storage keeps channels and individual lengths; features explicitly average channels to mono. Waveform inspection displays channel 0. Transcripts provide no timestamps, so gold timing is not recorded. The separate 32,000-sample sine teaching example remains labelled as teaching data.

Native references: [pycocotools mask conversions](https://github.com/cocodataset/cocoapi/blob/master/PythonAPI/pycocotools/mask.py), [COCO annotation-to-mask implementation](https://github.com/cocodataset/cocoapi/blob/master/PythonAPI/pycocotools/coco.py), [SciPy WAV PCM semantics](https://docs.scipy.org/doc/scipy/reference/generated/scipy.io.wavfile.read.html).

## Compatibility and verification

Edits in `domain/`, `vision/` and `speech/` change ADR 0014's strict implementation identity. **All earlier vision/NLP/speech checkpoints and registered domain versions require fresh training/registration after this update.** No manifest rewriting or weakened hash/environment checks. Tabular, CNN, RL and unsupervised identities/dependencies are unchanged. Import conversion lives in `connectors/` (already an installed editable package); canonical bytes and converter identity are pinned in imported provenance. No database migration or package reinstall is required.

`tests/test_domain_import.py` compares masks with `COCO.annToMask`, exercises all RLE forms/flip visibility/overlap, compares Unicode entity spans with seqeval and PCM with native SciPy (including signed 24-bit), checks bounded/path/schema/integrity refusals, optional-token enforcement, and executes actual three-family worker training → checkpoint → source-independent inference → production registration/reference. The false synthetic flag in one test deliberately checks **declaration transport** on generated test files, not whether that declaration is true. Public fixture generators/journeys always declare SYNTHETIC. Installed Chrome checks the actual import/apply/fresh-training/inspection/inference controls. HANDOFF §19 records commands, measured results and cleanup.

No real user dataset or real-world accuracy benchmark was supplied. Larger datasets, richer format variants, inferred/verified license status, automatic splits/groups, general data cleanup, deletion/retention, replayable import jobs and compatibility migration remain future work.
