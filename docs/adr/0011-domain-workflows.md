# ADR 0011: Typed domain workflows and recorded inspection (Milestone 6b)

Status: accepted. Builds on ADR 0002/0003 (immutable runs, typed values and recorded summaries). Sources: VISION §9.7–9.8, §23 Domain evidence, A56–A58.

## Decisions

1. A separate `domain` graph kind, `backend: python`, reuses the typed-value validator and node executor. Eleven operations use distinct wires: `image_batch+annotations`, `text_corpus`, `token_batch`, `audio_batch`, `feature_batch` and three report kinds. Contract metadata flows through static validation; mismatched box formats, sample rates and label policies/ignore indices fail before worker submission. Model, tabular and domain operations cannot mix silently.
2. Native libraries are installed and pinned on this CPython 3.13/macOS arm64 environment: torchvision 0.29.1, torchaudio 2.11.0, tokenizers 0.23.2, seqeval 1.2.2, torchmetrics 1.9.0, pycocotools 2.0.11, jiwer 4.0.0. Torchaudio imports and computes MelSpectrogram/resampling successfully; no SciPy fallback is needed. The existing PyTorch pin remains unchanged. Worker library versions are recorded, and tiny domain workers use one PyTorch intra-op CPU thread.
3. Vision image, instance rows, masks, box format/coordinate system, keypoints/visibility, flip pairs and sample metadata form one contract. torchvision v2 functional operations use tv_tensors. Boxes use continuous pixel edges (exclusive maximum); keypoints use continuous coordinates (pixel centers at i+0.5). torchvision KeyPoints flips use integer pixel centers, so the workbench explicitly converts the flip to W-x/H-y to preserve its declared convention. Flip pairs exchange both coordinates and visibility. After every geometry step, the declared policy clips/removes rows together and optionally refits boxes to remaining masks. Affine corner-enclosing boxes can be looser than masks and this is reported.
4. A tiny FCN trains on deterministic labelled SYNTHETIC drawn shapes. Validation IoU/Dice/pixel accuracy come from the aggregate confusion matrix and are checked against torchmetrics and hand calculations. Predicted foreground components become scored boxes; torchmetrics MeanAveragePrecision with pycocotools evaluates them. These are visibly labelled **derived detections**, not a separately trained detector.
5. NLP source labels are original character spans. Offline Hugging Face WordPiece fits on training sentences only. First-subword or all-subwords alignment is explicit; special tokens/padding and incomplete truncated words use the declared ignore index. Continuations change B-X to I-X under all-subwords. Validation reads each word's first subword prediction. Both conlleval-compatible default and strict IOB2 span conventions are tested against seqeval, including malformed predictions. The exact fitted tokenizer JSON and vocabulary hash are stored with the token output artifact.
6. Audio lengths are per channel, duration = N/sample_rate. The teaching sine is labelled and has exactly 32,000 samples/channel at 16 kHz for 2 seconds. Native torchaudio resampling uses ceil(N*target/source) samples. STFT frame count is 1+floor((N+2P-n_fft)/hop), with P=floor(n_fft/2) when centered and 0 otherwise; even centered FFTs simplify to 1+floor(N/hop). Actual frame counts are checked at runtime and against torch.stft, including odd FFTs. Feature computation occurs before batch padding; masks and sequence lengths cover only real frames.
7. The tone recognizer is Conv1d(stride 2) → packed bidirectional GRU → linear with native torch.nn.CTCLoss. It checks output lengths against label count plus adjacent repeats. Greedy decoding collapses repeats then removes blank 0. Output-frame centers link to feature-frame/sample time. These are greedy onset observations, not forced alignment or word timestamps. Edit-distance backtraces show substitutions/deletions/insertions; corpus CER/WER aggregate total edits over reference length and are tested against jiwer. Synthetic tones are visibly distinguished from speech.
8. All domains execute in real worker processes and write immutable CAS output/summary artifacts. Inspection only reads recorded bytes. Every view identifies run, graph, node, summary hash and sample; learned views identify validation and epoch. Source hashes, transform parameters, tokenizer normalization/policy, spectral configuration, CTC reduction and evaluation conventions remain inspectable. The project picker opens each example directly into its workspace; the graph canvas remains available. Structured transform/policy settings have working JSON editors that apply only valid JSON, then use normal graph validation.

## Limits

These are bounded CPU examples, not a complete domain framework: no pretrained weights, general COCO importer, detection-specific training architecture, language-model generation, streaming/beam speech decoding or multimodal fusion. Source blocks read the declared fixture formats. Models are trained during each run; summaries/predictions are persisted, but model/optimizer checkpoints and exact domain resume/export/inference serving are not implemented. Domain cancellation is currently checked between nodes, so an active training node finishes before cancellation is acknowledged. Vocabulary tie-breaking is native tokenizers behavior; the persisted tokenizer identity is authoritative. A seed alone does not claim byte-identical vocabularies across library/platform versions.
