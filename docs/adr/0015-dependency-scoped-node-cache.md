# ADR 0015 — Dependency-scoped node result cache for tabular graphs (A09)

Status: implemented within the bounds below, 2026-10-04. Builds on ADR 0001 (semantic hash excludes UI layout) and ADR 0003 (tabular graph kind).

VISION §18.2 requires cache keys that cover semantic configuration, input identity, implementation, environment, seed and partition context, and that editing a node invalidates only its dependents. Until now every tabular run re-executed every node. `python/tabular/cache.py` adds an opt-in, per-node cache to the existing node-by-node executor.

- **Key = everything the result depends on.** Operation type and version, node id (lineage and summaries record it), resolved configuration after any run-level seed override, a hash of every implementation file of the tabular operation family, the Python implementation/version and native library versions recorded in `run_started`, and each input's identity. A cacheable producer's identity is its own key; a source's identity is a hash of the content it actually read (CSV bytes of the table, dtypes, partition, lineage). Keys therefore propagate edits downstream and nowhere else. Partition context follows from the split's seeded key and the table identity.
- **Allowlist, not inference.** Only declared deterministic operations are cacheable: profile/duplicates/select/drop-missing, the seeded split, fitted impute/one-hot/standardize and their application, linear/logistic regression, metrics, predictions export, the SciPy statistics nodes and the seeded unsupervised nodes. Sources always run, because a file or database can change under unchanged settings. Connector sources, joins, code blocks, plugin operations and `domain` nodes (which train and record checkpoints) always run. An input with no content identity (a non-table result of a non-cacheable node) disables caching of its consumers rather than guessing. Folds and seeds are configuration, so fitted state is never reused across folds.
- **Opt-in per run.** `TabularRunConfig.cache` is `"off"` (default; no lookups, nothing recorded, existing behavior and events unchanged) or `"reuse"`. The editor's Run panel has a **Reuse unchanged node results (cache)** checkbox for tabular graphs.
- **Recorded, explained decisions.** `run_started` records the mode and implementation/environment hashes. Every `node_finished` records `cache: {status: hit|miss|bypass, key, reason, changed, fromRun, fromNode, entrySha256}`. A miss compares against the node's latest recorded entry for the same project and names what changed: `settings`, `implementation`, `environment`, or `input <port> (from <node>)`. The run summary and the editor's node-cache table show this in plain language.
- **Reused results are real recorded results.** A hit restores the native objects (DataFrames, fitted scikit-learn objects, SciPy results) recorded by an earlier execution, then records ordinary `node_output`/`node_summary` artifacts in the new run. Tests prove they are byte-identical to the original execution and to an uncached execution, including after edits and reverts.
- **Trust boundary.** Entries are pickles written only by this workbench's local worker into its own content-addressed store and indexed in the SQLite `node_cache` table. Each is SHA-verified, format- and key-checked before loading; a failed check becomes a miss and the node executes. There is no API to import, upload or write entries; remote-worker imports never enter the index. Entries above 64 MiB are not recorded (the node still runs and says so).
- **Retention (added later).** `GET /api/cache/nodes` reports entries, bytes and per-project counts. `POST /api/cache/nodes/prune` removes entries for an explicit project (or `allProjects`), optionally keeping the newest N per node or only dropping entries older than a given age. It defaults to a dry-run report. Index rows go first; an entry file is deleted only when no remaining index row or run artifact refers to the same bytes. Recorded run artifacts are never touched; a pruned result is recomputed (a miss) when next needed. A run that decided "hit" just before a concurrent prune fails the integrity check and recomputes the node. The editor's tabular Run panel shows the project's cache size with **keep only the latest per node** and **clear**, each previewed and confirmed.

Remaining: no automatic retention policy, no cache for model/procedure/agent/RL/domain graphs, no cross-workbench sharing, and no partial reuse inside a node. Editing any tabular implementation file intentionally invalidates every cacheable key (conservative). Cache hits skip native computation, so wall time is reduced but not measured as a benchmark claim.
