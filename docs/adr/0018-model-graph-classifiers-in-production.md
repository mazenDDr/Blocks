# ADR 0018 — Model-graph image classifiers in the local production registry

Status: implemented within the bounds below, 2026-10-04. Extends ADR 0012/0017 to the PyTorch model-graph workbench (reference CNN and similar image classifiers).

- **What is pinned.** A completed model-graph image-classification run (stored graph, recorded split, at least one complete checkpoint) is listed as a candidate whose node is the graph's single output. Registration pins:
  - the stored graph and the latest complete checkpoint, loaded with `weights_only` into the lowered graph with a strict state dict;
  - the input H×W from the validated graph, the training preprocessing and the class names from the split;
  - the last recorded epoch evaluation;
  - the Python/torch/pillow/numpy versions and the SHA-256 of every implementation file on the path (`production/model_adapter.py`, `graph_core/lower.py`, `graph_core/validate.py`, `operations/layers.py`, `operations/core.py`, `operations/_common.py`, `worker/dataset.py`).
- **Frozen reference, verified source.** Registration re-derives the image folder's identity with the training loader and requires it to equal the `dataset_sha256` and validation order recorded at training. Otherwise it is refused with `E_REFERENCE_SOURCE` and no reference is invented. It then copies up to 64 validation images and their recorded labels into the content-addressed store. Warmup, the reference-input view and monitoring use only that frozen reference. Serving never reads the source folder (a test moves it away and serving continues).
- **Serving.** Records are `{imagePng}`: base64 PNG/JPEG, RGB/RGBA/L, at most 1024 px per side, 1–32 per request within 8 MB. They pass through the exact training transform (`worker.dataset.preprocess_image`) and the lowered graph; the response carries class names, softmax probabilities and logits. Predictions equal `/api/infer` on the same checkpoint (test). Environment, implementation, checkpoint membership/completeness and pinned hashes are re-checked on every use; a changed implementation refuses serving (409). Releases, routes, admission, idempotency, capture/replay, traces, rollback and traffic are the shared ADR 0012 mechanisms.
- **Monitoring.** Ground truth is one class name per image; quality is accuracy on supplied labels only. Input drift compares per-image intensity mean/std (KS) with the frozen reference, and prediction drift compares predicted-class frequencies (total variation). The pinned model's accuracy on its own frozen reference is reported separately and labelled as not production traffic.
- **Editor.** Production lists "image classifier graph (PyTorch)" candidates and shows the pinned graph/checkpoint/preprocessing/classes/reference. **Load held-out validation images** fills the request and the labels. A browser journey trained the CNN in the editor and went through register → release → deploy → request → labels → monitoring. The model collapsed to one class after the editor's short default run (recorded val_acc 0.025), and monitoring reported accuracy 0 on its three labelled images, a real measurement, not a fabricated success.

Remaining: no serving for model graphs other than single-input image classifiers, no procedure-trained (sequence) models, agents, RL, unsupervised or Keras/JAX exports; no GPU/remote/multi-replica serving.
